Diaspora Payments — How Milestone Escrow works
01
Payer funds the escrow
The diaspora buyer deposits a stablecoin (USDC, cUSD) for the full agreed amount into a dedicated escrow contract — no intermediary custody, ever.
02
Milestones agreed upfront
Both sides define tranche amounts and conditions before any funds move — e.g. deposit, shipment, delivery.
03
Payee marks a milestone complete
Goods ship, a service is delivered, a phase finishes — the payee flags it on-chain.
04
Both approve, funds release
Dual-approval releases the tranche automatically. A dispute freezes it for an optional arbiter — or the payee auto-releases after a timelock if the payer goes silent.

Warehouse Trade Finance — How it works
01
Warehouse registers a batch
Grade, quantity, harvest season, and inspection report hash recorded as a new ERC-1155 token ID.
02
Financiers mint against the batch
Buyers or lenders hold tokens representing a claim on the physical goods sitting in storage.
03
Value tracked per batch
The warehouse operator updates the on-chain valuation as market rates shift.
04
Batches merge, expire, or redeem
Compatible batches consolidate on request; expired batches stop minting automatically.

Multi-Asset Pool Vault — How it works
01
Manager builds the basket
Whitelist accepted Ankara ERC-20 tokens and set target allocation weights — up to 50 tokens per vault.
02
Investors deposit, priced at NAV
Deposits mint pool tokens priced against the current oracle-fed net asset value.
03
NAV updates continuously
Total AUM and NAV-per-token read live oracle prices across every accepted token in the basket.
04
Withdraw a proportional basket
Burn pool tokens anytime to redeem your share of the underlying holdings — a management fee accrues automatically.

Token Factory
Deploy ERC-20, ERC-721, or ERC-1155 tokens from a single CLI command

The Token Factory deploys UUPS-upgradeable smart contract templates for every African asset class as lightweight ERC-1967 proxies. Configure via JSON, deploy in seconds — no Solidity knowledge required.

✓Fungible (ERC-20) — 6 templates for fractional ownership shares
✓Non-fungible (ERC-721) — 4 templates for unique asset records
✓Multi-token (ERC-1155) — warehouse batches and multi-asset pool vaults
✓Configurable templates via ankara.config.json
✓Mint, burn, pause, and role-based access on every template
📋
Asset Registry
Standard on-chain metadata schema for African asset classes

Links every token to its real-world asset. Defines a standardized metadata schema with IPFS/Arweave document linking, GPS coordinates, valuations, and full lifecycle management.

✓5-stage lifecycle: Draft → Active → Suspended → Redeemed → Expired
✓IPFS / Arweave document linking with hash verification
✓On-chain event emission for every state transition
✓Versioned metadata updates — fully auditable history
✓ERC-1155 batch minting — up to 50 token IDs per transaction
⚡
Transfer Engine
Identity-gated transfers without modifying core contracts

Every mint, burn, and transfer routes through a pre-transfer hook that checks the pluggable identity verifier on both sender and receiver — enforced at the contract level, not the app level.

✓Pre-transfer hooks — enforce KYC verification on every transfer when a verifier is set
✓Emergency pause halts all transfers, mints, and burns instantly
✓Milestone Escrow — tranche-based diaspora payments, see Use Cases below
✓ERC-1155 batch mint/burn for warehouse and pool operations
✓Full event log: sender, receiver, amount, timestamp, asset ID
🔐
Identity Hooks
Bring your own KYC provider — BVN, NIN, Smile Identity, or custom

Ankara Chain defines the IIdentityVerifier interface. You connect your chosen provider — without redeploying core asset contracts. African identity primitives built in.

✓Standard interface: verifyIdentity() · revokeIdentity() · isVerified()
✓Ships today: WhitelistVerifier reference implementation for testnet
✓Roadmap: Smile Identity integration for Nigeria BVN/NIN, Ghana Card, Kenya Huduma Namba
✓Swap providers without redeploying asset contracts
✓Bring your own KYC provider — implement the interface, plug it in

Multi-Chain Adapter
One API across four EVM chains and Stellar Soroban

Deploy to Ethereum, Polygon, BNB Chain, Celo, or Stellar without rewriting integration code — every template, factory, escrow, ramp, and asset-registry operation is available on both chain families behind the same IAdapter TypeScript interface.

✓Unified EVMAdapter API across Ethereum, Polygon, BNB Chain, and Celo
✓StellarAdapter for Soroban — same interface, same feature set, no capability gaps
✓Chain config via ankara.config.json or a custom RPC URL

Designed for developers who've never touched blockchain before. Full testnet token in 30 minutes — no Solidity required.

terminal 
# Install the SDK
npm install @ankarachain/sdk

# Scaffold a new project

deploy.ts 
import { TokenFactory } from '@ankarachain/sdk';

const factory = new TokenFactory({
  network: 'polygon-amoy',
  signer,
  factoryAddress: '0xYourFactoryAddress',
});

// Deploy a farmland token
const result = await factory.deployFarmland({
  name: 'Kano Farmland Token',
  symbol: 'KFT',
  assetId: 'KANO-FARM-001',
  countryCode: 'NG',
  metadata: { ... },
});

console.log(`Deployed: ${result.tokenAddress}`);
mint-asset.ts 
import { AssetRegistry } from '@ankarachain/sdk';

const registry = new AssetRegistry(adapter, tokenAddress, 'farmland');

// Mint fractional shares to an investor
await registry.mint(investorAddress, ethers.parseEther('1000'));

// Update the on-chain valuation as the asset appreciates
await registry.updateValuation(ethers.parseEther('150000'));
PortfolioWidget.tsx 
import { useAsset, useTokenBalance } from '@ankarachain/sdk/react';

export function AssetPortfolio({ tokenAddress, walletAddress }) {
  const { name, status, isLoading } = useAsset({
    tokenAddress, template: 'farmland', network: 'polygon-amoy',
  });
  const { formatted } = useTokenBalance({
    tokenAddress, walletAddress, network: 'polygon-amoy',
  });

  if (isLoading) return <Spinner />;

  return (
    <div className="portfolio">
      <h2>{name}</h2>
      <p>Your shares: <strong>{formatted}</strong></p>
      <p>Status: <Badge>{status}</Badge></p>
    </div>
  );
}
